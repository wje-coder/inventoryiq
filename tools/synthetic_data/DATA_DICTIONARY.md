# Synthetic Ecommerce Dataset — Data Dictionary

Generated by `generate.py` (fixed seed `42`, standard library only). Regenerate with:

```bash
python tools/synthetic_data/generate.py
```

This writes five CSV files to `tools/synthetic_data/output/` (gitignored — regenerate rather
than pull from git). A small, referentially-consistent slice of the same seeded output is
committed at `tools/synthetic_data/sample/` for quick inspection and for use as upload
fixtures without running the generator.

Date range: orders span **2023-01-01 through 2024-06-30** (18 months). Inventory snapshots
cover **14 consecutive months** starting 2023-01.

## products.csv

| Column | Type | Notes |
|---|---|---|
| `product_id` | string | `P00001`–`P00550`. Always present and well-formed (missing/malformed identifiers are injected at the *transactional* level in `order_items.csv`, not in the product master, to mirror how real bad data usually enters — through transactions, not catalog data). |
| `sku` | string | `SKU-{CAT}-{00001}` |
| `upc` | string | 12-digit UPC-A normally. **~3% intentionally malformed**: too short, contains letters, or blank. |
| `product_name` | string | Generated brand + adjective + noun. |
| `category` | string | One of 8 categories. **Intentionally inconsistent casing**: the same logical category appears as `Electronics`, `ELECTRONICS`, `electronics`, and `" Electronics "` across rows — normalize before grouping. |
| `brand` | string | Generated brand name. |
| `supplier` | string | One of 24 suppliers, non-uniformly distributed per category (supplier concentration pattern). |
| `unit_cost` | float | Category-specific cost range. |
| `retail_price` | float | `unit_cost × category margin multiplier`. |
| `status` | string | `active` (94%) or `discontinued` (6%). |

## orders.csv

| Column | Type | Notes |
|---|---|---|
| `order_id` | string | `O000001`–`O017000`. |
| `order_date` | string | ISO `YYYY-MM-DD` normally. **~0.5% intentionally invalid**: out-of-range month/day, non-date text, or `DD/MM/YYYY`-swapped format. Volume follows a **seasonal curve** (Nov/Dec peak ~1.8×, Jan/Feb trough ~0.75–0.8×). |
| `customer_id` | string | `C000001`–`C005000`, reused across orders (repeat customers). |
| `region` | string | `Northeast` / `Southeast` / `Midwest` / `West` / `Southwest`, non-uniform weights (**regional demand differences**), and each region is biased toward one product category. |
| `channel` | string | `online` (55%) / `retail` (30%) / `marketplace` (15%). |
| `status` | string | `completed` (90%) / `cancelled` (6%) / `pending` (4%). Only `completed` orders generate returns. |

## order_items.csv

| Column | Type | Notes |
|---|---|---|
| `order_item_id` | string | `OI0000001`–… |
| `order_id` | string | FK → `orders.order_id`. |
| `product_id` | string | FK → `products.product_id`. **~1.5% intentionally blank** (missing product identifier). |
| `quantity_sold` | int | 1–5, weighted toward 1. |
| `unit_sale_price` | float | Derived from `retail_price` with **seasonal discounts** (deeper in Nov/Dec). **~0.4% intentionally priced below the product's `unit_cost`**; **~0.25% intentional extreme outliers** (0.01×–80× the computed price). |
| `discount_pct` | float | 0–1, higher mean in Nov/Dec. |

**~0.5% of rows are exact duplicates** of other rows in this file (same values in every column, appended at the end) — an intentional data-quality problem, not a generation bug.

## returns.csv

| Column | Type | Notes |
|---|---|---|
| `return_id` | string | `R000001`–… |
| `order_item_id` | string | FK → `order_items.order_item_id`. |
| `return_date` | string | ISO date, 1–30 days after the order date. **A small fraction are intentionally invalid** (malformed text) or **before the order date** (data-quality problem). |
| `quantity_returned` | int | ≤ `quantity_sold` for that line item. |
| `reason` | string | One of: `defective`, `wrong_item`, `no_longer_needed`, `damaged_in_transit`, `not_as_described`, `better_price_found`. |

**Rising return rate pattern**: ~4% of active products are flagged internally as "problem
products" whose return probability climbs from ~5% early in the date range to ~45% by the end
— both a realistic quality-decline signal and a deliberately detectable anomaly for return-rate
trend analysis.

## inventory_snapshots.csv

| Column | Type | Notes |
|---|---|---|
| `snapshot_month` | string | `YYYY-MM`, one row per product per month, 14 months. |
| `product_id` | string | FK → `products.product_id`. |
| `region` | string | Snapshot region. |
| `quantity_available` | int | ~8% of products are stockout-prone (frequently 0), ~8% run excess inventory (800–3000 units), the rest fluctuate 20–400. **~1% of rows are intentionally negative** (data-quality problem — inventory counts should never be negative). |

## Summary of the 9 required intentional data quality problems

1. Missing product identifiers → `order_items.product_id` blank (~1.5%)
2. Duplicate rows → exact duplicate rows appended to `order_items.csv` (~0.5%)
3. Malformed UPC values → `products.upc` (~3%)
4. Negative inventory values → `inventory_snapshots.quantity_available` (~1%)
5. Invalid dates → `orders.order_date` (~0.5%) and `returns.return_date` (small %, including some before the order date)
6. Inconsistent category names → `products.category` casing variants
7. Sale prices below cost → `order_items.unit_sale_price` vs `products.unit_cost` (~0.4%)
8. Price outliers → `order_items.unit_sale_price` (~0.25%, 0.01×–80× normal)
9. Products with increasing return rates → the "problem products" subset described above

## Realistic business patterns included

Seasonality (order volume + discount depth), regional demand differences, category-specific
margins, discounts, returns, stockouts, excess inventory, supplier concentration patterns, and
the underlying revenue trend these combine to produce (visible when `order_items` is joined to
`orders` and aggregated by month).
